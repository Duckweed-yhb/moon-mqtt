SPIKE

QoS2 四步握手 + 断线自动重连 Spike

这不是普通 demo，是验证用的 spike：把 MQTT over WebSocket 的每一帧原始 hex 打出来，看 QoS2 的 PUBREC / PUBREL / PUBCOMP 全链路，以及 onclose 之后 1 秒自动重连、重连后重新 CONNECT + 重新订阅。

脚本加载中 … 最近一帧 — 已收 0 帧 最多重连 3 次

这个页面在跑什么

  • 连 wss://broker.emqx.io:8084/mqtt，发 CONNECT（client_id ws-spike），收 CONNACK。
  • 连上后由 core/ClientCore 纯函数自动产出 SUBSCRIBE，并在 SUBACK 后发一条 QoS2 PUBLISH（topic sensors/qos2），随后走完 PUBREC → PUBREL → PUBCOMP——这些字节全部由 MoonBit 状态机生成，页面侧一行握手代码都没有。
  • 产物内部每 12 秒会主动 close() 一次模拟断网：onclose → on_transport_close() → 1 秒后重连，最多 3 次，超过就放弃。

QoS2 发布握手：

PUBLISH(pid=1) → broker 回 PUBREC(0x50 02 00 01)
             → core.feed() 自动产出 PUBREL(0x62 02 00 01)
             → broker 回 PUBCOMP(0x70 02 00 01)
             → 在途清空。全程无手写握手字节。

断线重连：

onclose → on_transport_close() → state = Disconnected
  → 1s 后 reconnect attempt #1 → 新 CONNECT → 新 CONNACK
  → 自动 SUBSCRIBE(pid=2) + QoS2 PUBLISH → 继续收 PUBLISH
  → 最多 3 次（pid 递增 1→2→3）
  1. 浏览器侧与 Node 侧跑的是同一套 MoonBit core，页面只是换了 WebSocket 宿主。
  2. 完整记录见仓库 docs/WS-SPIKE.md。
