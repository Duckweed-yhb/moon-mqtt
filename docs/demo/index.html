这个页面在做什么

  • 连接公共 broker broker.emqx.io:8084（WebSocket + 子协议 mqtt，clean_session=false，每次刷新生成随机 client_id moon-demo-xxxxxx）。
  • 连上（CONNACK）后订阅 sensors/#，QoS1。
  • 收到 SUBACK 之后自动向 sensors/hello 发一条 QoS1 消息（payload hi，2 字节）——先订阅后发布，保证能在消息列表里看到自己收到的那条。
  • 连接断开后 1 秒自动重连，连续失败最多 3 次（成功连上后计数归零，长期在线不会耗尽配额）；每次重连都会重发 CONNECT、重新订阅。

点「强制断开（测试重连）」可以随时手动制造断线，看状态行从「已连接」→「重连中」→「已连接」的完整过程。公共 broker 偶尔限流或超时，刷新页面即可重试。

怎么判断跑通了（验收要点）
  1. 日志里依次出现：[demo] client_id=… → [browser] connecting to … → [demo] connected, subscribing sensors/# QoS1 → [demo] suback, publishing QoS1 sensors/hello。
  2. 消息列表出现 sensors/hello，payload hi，2 字节（这是 broker 回投给自己订阅的那条）。
  3. 点「强制断开」后，日志出现 [browser] reconnect attempt #1 in 1s，状态行变「重连中」，约 1 秒后重新 CONNECT 并再次订阅。
  4. 全程不依赖任何本地构建目录：页面只加载同目录的 ./browser-demo.js，所以 GitHub Pages 直接打开也能跑。
